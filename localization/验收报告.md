## 关键修复记录

1. **CRLF 偏移错位**：提取器按 LF 归一化导致偏移偏移，改为 `newline=""` 保留原始行尾。
2. **JS 字符串引号边界**：回填断言需同时比对包裹引号，避免误判。
3. **代码键误译**（关键）：`sigilResetterModes`（`game["sigilResetter"+值]`）、符印类型 `<option>`（`sigilColours.indexOf(value.toLowerCase())`）的值实为代码键，翻译后导致通关存档加载崩溃。已在提取阶段按源码上下文加入保护：`CODE_KEY_ARRAYS`、`CODE_KEY_SELECT_IDS`。修复后运行时错误从 1 降为 0。
4. **供应商前缀**：中文字体回退加入 `Microsoft YaHei`，避免原版 `MS Sans Serif` 无中文字形。
5. **游戏名汉化**：`DodecaDragons` 原按品牌名保留，现统一译为「十二龙」，覆盖 `<title>`、`og:title`、窗口标题栏、主界面大标题、通关画面共 5 处；无任何 JS 代码键引用该名，全局替换安全。英文版保持原文不变。
6. **切换按钮位置**：由右上角浮动按钮改为注入「设置」面板 window-body 顶部（两版均有），避免遮挡；需打开设置面板才能点按，往返切换及存档兼容复验通过。
7. **残局试玩覆盖正式存档**：原版自带 `setInterval(save, 5000)`，演示版未调用 `load()` 却仍会定时写 `dodecaSave`。在演示版游戏脚本加载前注入 `Storage.setItem` 屏蔽器（仅拦截 `dodecaSave` / `dodecaLastSaved`）与 `DD_DEMO` 标记；实测 6 秒后哨兵存档保持不变。
8. **自动存档保险层（不改源码）**：游戏本体已有 5 秒自动保存，额外在构建产物中注入运行时脚本，监听 `pagehide` / `beforeunload` / `visibilitychange`，在关闭页面或切到后台时立即补存，并在设置面板显示最近保存时间；原版 JS 文件零改动。
9. **“有自动保存仍丢档”的三个真实成因（已复现并修复）**：
   - **慢加载抢写**：`setAutoSave()` 在 `script.js` 顶层就启动，5 秒后 `load()` 才在页面末尾执行；若脚本加载超过 5 秒（慢网络 / 手机），内置 autosave 会先把 `reset()` 的空档写进 `dodecaSave`，随后 `load()` 读回空档。延迟 `achievements.js` 6.5 秒可稳定复现。
   - **加载失败被覆盖**：`load()` 里 `JSON.parse` 无 `try/catch`，坏档/旧档使其抛错；但 autosave 定时器已启动，5 秒后把空档写进去，原档彻底消失。
   - **多标签页互覆盖**：每个标签页各自每 5 秒写同一个 key，后写覆盖先写；旧的后台标签页会把新档改回旧档。
   修法（同样只改构建产物）：在游戏脚本加载前注入守卫，拦截 `dodecaSave` / `dodecaLastSaved` 的 `setItem`，直到 `load()` 成功（以 loadingCover 隐藏为标志）才放行；监听 `storage` 事件，发现其他标签页写入更新的 `lastSave` 就把本页标记为 stale 并停止写入、显示提示。三项复测全部通过。

## 第二轮修复（2026-11-25）

### 1. 符印无法重置（切英文才能重置）

**根因**：词典把 `"Sigils"` 当作界面文本译成了「符印」，而它在源码里是拼接代码键的片段：

```js
let sigilName = sigilColours[x - 1] + "Sigils";   // 被译成 + "符印"
game[sigilName + "ToGet"]                        // -> game["cyan符印ToGet"] === undefined
```

于是 `sigilsGained.isNan()` 直接抛 `TypeError`，点「重置此前所有进度以获得 N 青色符印」毫无反应；知识交易页 `purchaseKnowledgeTrade()` 里同样有 4 处这样的键，购买判定也一并静默失效。英文版字符串未被翻译，所以只有切英文才正常。

**修法**（`tools/build.py` 新增 `restore_code_keys()`）：构建末尾把颜色名后拼接的 `+ "符印"` 强制还原成 `+ "Sigils"`，覆盖 `sigils.js` 1 处与 `knowledge.js` 4 处，重建也不会回退。

**验证**：无头 Edge 载入通关存档，点真实按钮 `<button onclick="sigilCheck(1)">`，青色符印 `ee23.22462559947787 → ee23.224626215495544`（正好等于 `cyanSigilsToGet`），`lastSigilReset` 更新，无 JS 报错；`purchaseKnowledgeTrade(1)` 后知识 `ee23.237795836021544 → ee23.237796596794702`、蓝符印同步扣减。

### 2. 龙取名支持中文

**根因**：`exportGame()` 用 `btoa(JSON.stringify(game))`，`btoa` 遇到 Latin-1 以外的字符（中文龙名）直接抛 `InvalidCharacterError`，导出失败；即便拿到串，`atob` 得到的是二进制串，中文也变乱码。存档本身（`localStorage`）不受影响，坏的只是导入导出。

**修法**：`script.js` 的导入导出换成 UTF-8 安全编解码 —— 导出 `TextEncoder → base64`，导入 `base64 → TextDecoder(fatal) → JSON.parse`，fatal 失败时回退按原样解析，兼容旧版纯 ASCII 存档；顺带支持粘贴原始 JSON 与 URL-safe base64。

**验证**：龙名设为「测试龙·小红」→ 导出串为标准 base64 → `ddDecodeSave` 解回中文名 → 清空后 `importGame()` 名称复原；英文版同样通过。

### 3. 存档新增文件格式导入 / 导出

设置面板在「导出 / 导入」下方新增一行「导出文件 / 导入文件」：

- **导出文件**：`ddDownloadSave()` 走 Blob 下载，文件名 `十二龙-存档-YYYYMMDD-HHMMSS.txt`，内容为 UTF-8 base64（与剪贴板串同格式，可互相粘贴）。
- **导入文件**：隐藏的 `<input type="file" accept=".txt,.json,.sav,.save">` + `FileReader`，读取后先确认再 `reset()+loadGame()`，随后立即保存；同时接受 base64 文本与原始 JSON 存档。
- 两个按钮在两版中都注入（英文版为 Export file / Import file），文案随语言走。

**验证**：捕获到下载文件 `十二龙-存档-20261125-123520.txt`（14,717 字节）；把内存里的龙名改脏后用 `setInputFiles` 导入该文件，名称恢复「测试龙·小红」；旧式 `btoa(JSON)` 纯 ASCII 存档仍可导入（unlocks=37）。

### 6. 源头上堵住复发（提取器加固）

`tools/extract.py` 原来只靠 `CODE_KEY_ARRAYS`（`sigilResetterModes`）与 `CODE_KEY_SELECT_IDS`（`sigilResetterType`）两份白名单避免误译，裸片段 `"Sigils"` 不在白名单里，于是漏了。现在新增两条通用规则：

- `property_access_ranges()`：凡 `ident[...]` 形式的成员访问方括号内部一律视为代码，整段跳过（覆盖 `game[colour + "Sigils"]`、`game["knowledgeTrade" + trade + "Amounts"]`）。
- `identifier_fragment_ranges()`：标识符形状（无空格）且紧贴 `+` 或 `=== / != / case` 的字面量视为代码片段（覆盖 `"Sigils"`、`'fireUpgrade'`、`"dragonName"`），带空格的展示片段不受影响。

回归测试 `tools/test_extract_guards.py`：5 个必保护点全部命中，2 条展示文案（重置确认弹窗、「已复制到剪贴板」）不被误伤。该改动只影响"下次重新提取"，不改变现有构建产物。
